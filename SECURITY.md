# ReachWeaver security policy

**Experimental, community-maintained software.** This file explains how to report possible security vulnerabilities; it is not a warranty or a support-service agreement.

## Supported releases

Security fixes are developed against the latest `main` branch of [ReachWeaver](https://github.com/MSKazemi/reachweaver). Older releases do not currently have a guaranteed maintenance or response schedule. Check the latest release notes and [detailed security documentation](docs/SECURITY.md) before deploying.

## Report vulnerabilities privately

**Do not disclose vulnerabilities, credentials, exploit details, private drafts, cookies or access tokens in public issues or pull requests.**

1. Email **mohsen.seyedkazemi@gmail.com** privately with the subject `ReachWeaver security`. Describe the affected version, suspected impact and a safe reproduction where possible. **Never email a working password or token**; revoke exposed credentials at their original provider first.
2. If [GitHub private vulnerability reporting](https://github.com/MSKazemi/reachweaver/security/advisories/new) is enabled for this repository, you may use that private reporting form instead. The link may be unavailable when the owner has not enabled the setting; do **not** assume it is active.
3. If no private channel is accessible, a public GitHub issue may only request a private contact method **without any vulnerability details**.

The maintainer will review reports when reasonably able, but makes no guaranteed response time, support commitment or absolute security assurance. Accounts, compromised credentials and remote content remain under their owners' control.

See [the detailed security and residual-risk policy](docs/SECURITY.md), [responsible-use notice](DISCLAIMER.md), [privacy notice](docs/PRIVACY.md) and [security checklist](docs/SECURITY-CHECKLIST.md).
